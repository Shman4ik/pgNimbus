Статус: пакеты A–E, F (области видимости), G (контексты PostgreSQL и JOIN) и H (функции и типы) реализованы; I–J — впереди. Ниже — исходный аудит без изменений.

## 1. Решение

Главный следующий шаг — сделать подсказки точными для текущего места в запросе.
Сейчас полезные функции опираются на разрозненные эвристики. Они смешивают области видимости и иногда предлагают некорректный SQL.

Рекомендуемый порядок:

1. Исправить границы SQL-команд, разрешение имён и замену текста при принятии подсказки.
2. Ввести общий лексер и разбор незавершённого SQL с областями видимости.
3. Добавить контекстные подсказки для JOIN, функций, типов и основных команд PostgreSQL.
4. Измерить задержки всего пути ввода и ограничить работу на UI-потоке.

Новые постоянные кнопки не нужны. Основной интерфейс — существующий список подсказок, клавиатура и небольшая панель аргументов у курсора.
Вторичные действия остаются в палитре команд. Это соответствует [правилам Nimbus](../../shared/nimbusUi/DESIGN.md).

## 3. Как работает текущая реализация

| Участок | Реализация | Что уже полезно |
| --- | --- | --- |
| Запуск и показ подсказок | `QueryEditorPanel.OnSqlTextEntered`, `ShowCompletion`, `ApplyFuzzyFilter` | Буква, `_`, точка, запятая, пробел после части ключевых слов, Ctrl+Space |
| Получение кандидатов | `SqlCompletionProvider.GetCompletionData` | Колонки по алиасу, таблицы по схеме, сужение после FROM и WHERE |
| Контекст курсора | `SqlCompletionContext.GetCaretContext` | Комментарии, простые строки, последний распознанный раздел SQL |
| Таблицы и CTE | `ExtractTables`, `ExtractCteDefinitions` | Простые FROM/JOIN, UPDATE/INTO, CTE, часть выходных колонок |
| Ранжирование | `CompletionRanker`, `FuzzyMatcher`, `CompletionRecency` | Нечёткий поиск, приоритеты контекста, последние 50 принятых имён |
| JOIN | `ForeignKeyMatcher` | Подъём связанных таблиц, условие по FK, составные ключи |
| Вставка | `SqlCompletionData.Complete`, `MaybeInsertTableAlias` | Кавычки для таблиц/колонок, `function()`, курсор в скобках, автоалиас |
| Разбиение скрипта | `SqlScriptSplitter` | Команды между `;`, комментарии, кавычки, dollar-quoted строки |
| Форматирование | `SqlFormatter` | Собственный токенизатор и проверка сохранения токенов |
| Browse-режим | `BrowseSqlParser` | Ограниченный разбор запросов, которые поддерживает редактируемая таблица |
| Определение типа команды | `SqlStatementInspector` | EXPLAIN, изменения данных, консервативная проверка повторного выполнения |

Полного общего SQL-парсера сейчас нет. Есть несколько специализированных сканеров и регулярных выражений.
Это допустимо для узких задач, но правила строк, идентификаторов и вложенности уже расходятся.
`BrowseSqlParser` не нужно превращать в универсальный парсер: отказ от неподдерживаемого запроса является частью его контракта.

Каталог загружается при обновлении. На каждый символ запросов к базе нет — это необходимо сохранить.
`RefreshAsync` последовательно получает таблицы, колонки и функции каждой включённой схемы, затем FK.
Число обращений составляет примерно `3 × число схем + 2`.
Для таблиц используется `GetTablesAsync`, который также вычисляет размеры отношений. Автодополнению эти размеры не нужны.

## 4. Подтверждённые проблемы

В примерах `|` обозначает курсор и не является частью SQL.
Проверочный каталог: `public.users(id, name)`, `audit.users(id, audit_only)`, `public.orders(id, user_id, total)`.

### F01. Подсказки выходят за границы SQL-команды — P0

```sql
SELECT * FROM public.users u;
SELECT * FROM public.orders o WHERE |
```

**Воспроизведено:** список колонок содержит `id`, `name`, `user_id`, `total`.
`name` попадает из предыдущей команды. Команда справа от курсора также влияет на подсказки предыдущей команды.

Причина: `QueryEditorPanel` передаёт весь буфер. Провайдер вызывает `ExtractTables` и `ExtractCteDefinitions` для всего текста.
Сброс раздела SQL после `;` в `GetCaretContext` не ограничивает поиск таблиц.

**Требование:** анализировать всю текущую команду, включая FROM справа от курсора, но исключать соседние команды.
После завершающего `;` пустая область должна получать контекст новой команды.
Нельзя напрямую наследовать правило `StatementSpanAt`, которое в пустом конце выбирает предыдущую команду для Run/Format.

### F02. Имена разрешаются иначе, чем в PostgreSQL — P0

```sql
SELECT * FROM users u WHERE u.|
SELECT * FROM missing.users u WHERE u.|
SELECT public.users.| FROM public.users
```

**Воспроизведено:** каждый пример предлагает `id`, `name`, `audit_only`.

Причины:

- `_columnsByTable` объединяет колонки одноимённых таблиц под коротким именем.
- `ColumnsFor` при отсутствии явно указанной схемы в кеше откатывается к короткому имени даже для `missing.users`.
- `GetQualifierBeforeCaret` возвращает только последнюю часть цепочки перед точкой.
- Словари и сравнения часто используют `OrdinalIgnoreCase`, теряя различие quoted identifiers.

**Требование:** отдельная идентичность объекта `(schema, name, kind)`, желательно с OID внутри снимка каталога.
Короткие ссылки разрешать по достоверному `search_path`, не объединять.
Если указанная схема не найдена, возвращать неизвестный объект без подстановки другой схемы.
Сохранять исходное написание, признак кавычек и нормализованное имя каждого сегмента.

PostgreSQL приводит некавыченные имена к нижнему регистру и различает регистр внутри кавычек.
Поиск короткого имени зависит от порядка схем. Источники: [идентификаторы](https://www.postgresql.org/docs/18/sql-syntax-lexical.html), [search_path](https://www.postgresql.org/docs/18/ddl-schemas.html).

### F03. Подзапрос ломает внешний контекст — P0/P1

```sql
SELECT * FROM public.users
WHERE id IN (SELECT user_id FROM public.orders) AND |
```

**Воспроизведено:** контекст равен `FromTableRef`, хотя курсор находится в условии внешнего WHERE.
Сканер хранит один раздел SQL и не восстанавливает его при закрытии скобки.

Вариант с `EXISTS (SELECT … WHERE …)` сохраняет `Predicate`, но предлагает колонки внутренней таблицы во внешнем запросе.

```sql
SELECT q.| FROM (SELECT id AS customer_id FROM public.users) q
```

**Воспроизведено:** колонок нет. Выходная колонка `customer_id` не разрешается.

**Требование:** дерево областей видимости для блоков SELECT, CTE и производных таблиц.
Каждый блок хранит источники, выходные колонки, родителя и текущий раздел SQL.
Коррелированные ссылки доступны только там, где их допускает PostgreSQL.
Обычный подзапрос в FROM и LATERAL требуют разных правил. См. [табличные выражения](https://www.postgresql.org/docs/18/queries-table-expressions.html).

### F04. Строки обрабатываются несовместимыми способами — P0

```sql
SELECT E'can\'t |';
SELECT $tag1$hello |$tag1$;
SELECT $тег$hello |$тег$;
```

**Воспроизведено:** во всех трёх случаях `InStringOrComment == false`.
Внутри строки провайдер может открыть подсказки. Тот же флаг используется для автоматического закрытия скобок и кавычек.

```sql
SELECT E'can\'t;stop'; SELECT 2;
```

**Воспроизведено:** `SqlScriptSplitter.Split` возвращает два неверных фрагмента:

```text
SELECT E'can\'t
stop'; SELECT 2;
```

При этом splitter правильно обрабатывает `$tag1$a;b$tag1$`, который не распознаёт сканер completion.
Это влияет также на выбор команды для Run и Explain через `SqlScriptSplitter`.

**Требование:** общий лексер с едиными правилами `E'…'`, `''`, `"…"`, `""`, dollar quoting и вложенных комментариев.
Незавершённые токены должны иметь явное состояние. Они не являются ошибкой самого редактора.
Для `standard_conforming_strings` нужен явный режим, а не разные скрытые предположения в потребителях.
Лексические правила: [PostgreSQL 18](https://www.postgresql.org/docs/18/sql-syntax-lexical.html).

### F05. Общая колонка JOIN вставляется неоднозначно — P0

```sql
SELECT * FROM public.users u
JOIN public.orders o ON u.id = o.user_id
WHERE |
```

**Воспроизведено:** провайдер предлагает единственный `id` с вставкой `id`.
Колонки схлопываются по подписи. У обеих таблиц есть `id`, поэтому такая ссылка неоднозначна.

**Требование:** предлагать `u.id` и `o.id` как разные варианты.
Для уникальных имён можно сохранять короткую вставку.
При JOIN USING учитывать объединённую выходную колонку, а не считать любой повтор имени неоднозначным.
Самосоединение должно хранить две ссылки на один объект с разными алиасами.

### F06. CTE теряет происхождение `alias.*` — P1

```sql
WITH x AS (
    SELECT u.* FROM public.users u JOIN public.orders o ON true
)
SELECT x.| FROM x
```

**Воспроизведено:** доступны `user_id` и `total`, хотя `u.*` выбирает только колонки `users`.
`CteDefinition` хранит один флаг `SelectsStar`, без указания источника конкретной звёздочки.

```sql
WITH x AS (DELETE FROM public.orders RETURNING id)
SELECT x.| FROM x
```

**Воспроизведено:** колонок нет. Выходной список RETURNING не анализируется.

**Требование:** представлять каждый элемент проекции отдельно: имя, выражение, `*`, `alias.*` и происхождение.
Использовать ту же модель для CTE, подзапросов и RETURNING.
Неразрешённый CTE должен скрывать одноимённую таблицу каталога даже при неизвестных колонках.

### F07. Раскрытие `*` меняет форму результата с USING — P0

```sql
SELECT * FROM public.users u JOIN public.orders o USING (id)
```

**Воспроизведено:** замена равна `u.id, u.name, o.id, o.user_id, o.total`.
Исходный USING выводит общую колонку один раз. Подстановка добавляет лишнюю колонку.
Для OUTER JOIN значение общей колонки также нельзя всегда заменить ссылкой на одну сторону.

**Требование:** сначала запретить преобразование, когда точная форма результата неизвестна.
Затем раскрывать `*` по выходной структуре JOIN с учётом USING/NATURAL и порядка колонок.
При отказе показать короткую причину через существующий механизм уведомлений.
Правила USING: [документация PostgreSQL](https://www.postgresql.org/docs/18/queries-table-expressions.html).

### F08. Функции теряют схему, кавычки и перегрузки — P1

**Воспроизведено:** `FunctionItem` для `custom."MyFunc"` вставляет `MyFunc()`.
Два кандидата-функции с одинаковым именем схлопываются в один, даже при разных схемах.

**По коду:** функции и процедуры попадают в общий набор. `schema.` ищет таблицы, но не функции.
Подсказка сигнатуры существует как tooltip строки. Отдельной подсказки текущего аргумента после вставки нет.

**Требование:** корректная квалификация и кавычки, сохранение перегрузок, разделение функций и процедур.
После `CALL` предлагать процедуры. В выражении предлагать допустимые функции.
Сигнатуры перегрузок можно объединять под одним именем, но пользователь должен видеть все подходящие варианты.

### F09. Все виды JOIN получают одинаковое продолжение — P1

**Воспроизведено:** `IsAfterCompleteJoinTarget` возвращает `true` после `CROSS JOIN public.orders `.
Провайдер использует этот результат для повышения приоритета ON/USING.
Для CROSS JOIN такое продолжение неверно. NATURAL JOIN также требует отдельного контекста.

**По коду:** `ForeignKeyMatcher.BuildJoinCondition` выбирает первую найденную связь с ближайшей подходящей таблицей.
Два FK между одной парой таблиц не представлены как выбор.
Редактирование раннего JOIN может учитывать более поздние JOIN, поскольку список таблиц относится ко всей команде.

**Требование:** распознавать вид и текущий узел JOIN.
Для нескольких FK показывать отдельные условия с названием ограничения и колонками.
Для USING предлагать общие колонки двух сторон текущего JOIN.

## 5. Риски взаимодействия, видимые по коду

Эти случаи требуют отдельной проверки клавиатурой. Аудит не утверждает, что каждый уже воспроизведён в окне приложения.

| Сценарий | Основание | Требуемое поведение |
| --- | --- | --- |
| Ctrl+Space после `sel` | `ShowCompletion(false)` не отступает к началу слова | Фильтр `sel`, замена слова целиком, результат `SELECT` |
| Дополнение внутри `cust|omer_id` | Нет явного вычисления правой границы токена | Заменить выбранный токен без дублирования суффикса |
| Принятие функции перед существующей `(` | `Complete` всегда вставляет готовое `name()` | Одна пара скобок, корректная позиция курсора |
| Принятие таблицы перед уже набранным алиасом | `MaybeInsertTableAlias` не проверяет правый текст | Сохранить существующий алиас |
| Один Undo после table completion | Автоалиас вставляется через `Dispatcher.Post` | Таблица и автоалиас отменяются одной операцией |
| Быстрое переключение вкладки после accept | Отложенный автоалиас читает текущий редактор | Вставка привязана к исходному документу и версии |
| Нет совпадений, затем Backspace | Используется `Hide()`, а ссылка на окно остаётся | Подсказки снова показываются при появлении совпадений |
| Повторный Ctrl+Space | Перед созданием нового окна нет явного закрытия старого | Одно окно и один набор подписок |
| Фильтрация и выбор стрелками | Каждый пересчёт заново выбирает лучший элемент | Сохранить явный выбор пользователя, пока он подходит |

Отдельно **воспроизведено** отсутствие подсказок внутри незакрытого quoted identifier: `WHERE "na|`.
`GetCaretContext` объединяет quoted identifier со строкой. Для пользователя это именно место, где нужно дополнение имени.

## 6. Контракт удобного ввода

### 6.1. Клавиатура и вставка

- Ctrl+Space открывает подсказки для полного префикса текущего токена. На macOS сохранить существующее исключение Ctrl+Space.
- Tab принимает выбранную подсказку. При закрытом списке сохраняется обычный отступ.
- Enter принимает явно выбранную строку или уверенное точное/префиксное совпадение.
- Для автоматически открытого списка с пустым префиксом или слабым fuzzy-совпадением Enter вставляет новую строку.
- Явным выбором считать стрелки, мышь и явный вызов Ctrl+Space. Визуально различать предварительную и активную выборку.
- Escape закрывает список до следующего изменения токена или нового смыслового триггера. Движение курсора само по себе его не открывает.
- Пробел, запятая и `;` не принимают fuzzy-кандидата автоматически.
- Точка после уже написанного алиаса открывает его колонки. Слабая подсказка не заменяет алиас перед точкой.
- Вставка, скобки и автоалиас составляют одну операцию Undo.
- При вставке нескольких символов, paste и IME не обрабатывать первый символ как отдельное нажатие.

Поведение Enter является предлагаемым продуктовым решением. Его нужно проверить на сценариях быстрого набора и переноса строк.
Если потребуется настройка совместимости, разместить её в Preferences, без нового элемента toolbar.

### 6.2. Содержимое подсказок

| Положение курсора | Основные кандидаты |
| --- | --- |
| Начало команды | SELECT, WITH, INSERT, UPDATE, DELETE и другие допустимые команды |
| FROM/JOIN | CTE текущей области, доступные отношения, табличные функции в подходящем контексте |
| SELECT до уже набранного FROM | Колонки источников этого блока, даже если FROM расположен справа |
| WHERE/ON | Колонки доступных источников, функции и операторы |
| ORDER BY/GROUP BY | Допустимые выходные имена и входные колонки с правилами PostgreSQL |
| INSERT INTO t (`|`) | Колонки целевой таблицы, с исключением уже перечисленных |
| UPDATE t SET `|` | Колонки цели слева от `=`, выражения справа |
| ON CONFLICT | Колонки/ограничения для conflict target, затем DO NOTHING или DO UPDATE |
| DO UPDATE SET | Колонки цели и допустимые ссылки `excluded.column` |
| RETURNING | Выходные выражения текущей DML-команды |
| `value::|` | Встроенные и пользовательские типы, домены |
| `OVER (PARTITION BY |)` | Колонки текущей области и соответствующие продолжения окна |
| `schema.|` | Объекты схемы, допустимые именно в этой позиции |
| `"Order I|"` | Имена в quoted identifier с корректным экранированием |

Выходные алиасы не следует предлагать в WHERE только потому, что они доступны в ORDER BY.
Одинаковые подписи не являются одинаковыми объектами. См. [правила SELECT](https://www.postgresql.org/docs/18/sql-select.html).

### 6.3. Ранжирование и подписи

Сначала отсечь недопустимые объекты. Затем ранжировать:

1. Точное совпадение имени.
2. Совпадение начала имени.
3. Совпадение начал частей имени, затем прочий fuzzy-поиск.
4. Внутри группы: текущая область, источник/тип в контексте, локальная история, стабильный порядок.

Для пустого префикса показывать полезные продолжения, а не весь каталог.
В WHERE неизвестный источник не должен автоматически возвращать все колонки базы.
Оставлять ключевые слова, функции и известные локальные имена. Ручной Ctrl+Space может расширять поиск явным действием.

У колонки показывать тип и источник, у отношения — схему, у функции — схему и сигнатуру.
Не увеличивать высоту строк ради подробностей. Полное описание остаётся в боковой подсказке.
Историю принятия хранить по идентичности объекта, а не только по подписи.

### 6.4. Функции и локальные подсказки

После `function(` показывать сигнатуру и выделять текущий аргумент.
При запятой учитывать вложенные вызовы, строки и массивы.
Поддержать именованные аргументы и перегрузки без необходимости повторно открывать completion.
Тип использовать как мягкий сигнал: не скрывать допустимый вариант из-за неизвестного типа или неучтённого приведения.

Позднее добавить небольшие шаблоны для CASE, EXISTS, ON CONFLICT и оконных функций.
Шаблоны должны иметь переход между полями по Tab и единый Undo.
Генерация SQL через LLM не требуется для этой версии.

## 7. Архитектура реализации

### 7.1. Общий лексер и терпимый разбор

Рекомендуется управляемая реализация в Core без UI-зависимостей и новых обязательных пакетов на первом этапе.
Разбирать поддерживаемые конструкции постепенно. Не пытаться сразу воспроизвести всю грамматику PostgreSQL.

```text
DocumentSnapshot + caret + catalog version
                  ↓
SqlLexer → StatementIndex → SqlSyntaxSnapshot
                                  ↓
                          ScopeResolver
                                  ↓
                         CompletionService
                                  ↓
                     CompletionCandidate + TextEdit
                                  ↓
              App: ranking session, popup, accept, undo
```

| Новый контракт, рабочее имя | Минимальное содержимое |
| --- | --- |
| `SqlToken` | Kind, Start, Length, RawText, NormalizedName, IsQuoted, IsIncomplete |
| `SqlSyntaxSnapshot` | DocumentId, Version, токены, команды, блоки, восстановленные узлы |
| `SqlScope` | Parent, Sources, Ctes, OutputColumns, JoinNodes, видимость внешних ссылок |
| `CatalogSnapshot` | ConnectionGeneration, Version, идентичности объектов, колонки, функции, FK, контекст сессии |
| `CompletionRequest` | DocumentId, Version, CaretOffset, TriggerKind, CatalogVersion |
| `CompletionCandidate` | StableId, Kind, DisplayText, FilterText, Detail, RankClass, Confidence |
| `CompletionEdit` | ReplaceStart, ReplaceLength, InsertText, CaretOffset, связанные правки |

Это эскиз контрактов, а не требование создать по классу на каждую строку.
Смещения в редакторе хранить в UTF-16, как в AvaloniaEdit. Любая внешняя библиотека должна явно конвертировать свои смещения.

Разбор должен восстанавливаться на незакрытых скобках, пустых выражениях и частично написанных ключевых словах.
Синхронизация выполняется на границах текущего блока. Ошибка одного CTE не должна уничтожать внешний SELECT.
Вместо ложного разрешения возвращать `Unknown` с известной частью контекста.
Ограничить глубину вложенности и поддержать отмену обработки больших документов.

### 7.2. Почему не подключить полный парсер сразу

| Вариант | Польза | Цена и ограничение | Решение |
| --- | --- | --- | --- |
| Продолжать расширять regex | Быстрые точечные исправления | Сложно моделировать вложенность, восстановление и происхождение колонок | Только временные исправления P0 |
| Общий managed-лексер и частичный parser | Контроль над незавершённым SQL, совместимость с текущей архитектурой | Команда поддерживает выбранное подмножество грамматики | Основной путь, проверять на корпусе сценариев |
| Tree-sitter | Инкрементальный разбор и устойчивость к ошибкам | Нужны PostgreSQL-грамматика, .NET-интеграция, native packaging и отдельный resolver | Ограниченный сравнительный прототип перед расширением грамматики |
| libpg_query | Реальный parser PostgreSQL вне сервера | Не решает completion/resolution. Восстановление незавершённого ввода нужно проектировать отдельно | Кандидат для эталонных проверок завершённого SQL |
| SQL language server | Возможность повторного использования языка редактора | Отдельный процесс, протокол, запуск и проверка качества PostgreSQL | Отложить до подтверждённой потребности |

Характеристики библиотек: [Tree-sitter](https://tree-sitter.github.io/tree-sitter/), [libpg_query](https://github.com/pganalyze/libpg_query).
Выбор основного пути — вывод этого аудита из требований проекта, а не результат сравнительного benchmark библиотек.

Прототип альтернативы ограничить 2–3 рабочими днями.
Сравнить восстановление на матрице ниже, задержки, лицензию, поддержку PostgreSQL и публикацию NativeAOT.
Проверить `win-x64`, `osx-arm64`, `linux-x64`, `linux-arm64`.
Новая обязательная зависимость Core потребует явного изменения архитектурного правила в AGENTS.md.
До положительного результата не включать её в приложение.

### 7.3. Каталог и сессия

- Публиковать один неизменяемый снимок каталога вместо нескольких независимо заменяемых полей.
- Присваивать каждому обновлению номер. Старый запрос не может перезаписать более новый снимок.
- Отменять загрузку при смене соединения и закрытии окна.
- Сохранять предыдущий снимок при ошибке обновления. Через существующую поверхность статуса сообщать, что данные устарели.
- Показывать ключевые слова и базовые функции до окончания загрузки каталога.
- Загружать имена отношений без вычисления размеров. Объединять запросы по выбранным схемам или ограничивать параллелизм.
- Сохранить исключения схем. Исключённые схемы не должны попадать обратно через FK-кандидаты.
- Обновлять нужную часть каталога после успешно выполненного DDL. Не запускать полную загрузку при каждом символе.
- Получать `search_path` и версию PostgreSQL из контекста исполнения. Не считать настройку другого pooled-соединения достоверной.
- В явной транзакции учитывать её held connection, локальные настройки и временные объекты.
- Если контекст сессии неизвестен, предлагать явно квалифицированные варианты и не выдумывать разрешение короткого имени.

DDL-события должны исходить из факта успешного выполнения, а не только из текста незавершённого запроса.
Серверные metadata-запросы не должны мешать потоку результатов или отмене QueryEngine.

### 7.4. Совместимость остальных потребителей

Переводить `SqlScriptSplitter`, completion, formatter и BrowseSqlParser на общую лексику по очереди.
Для каждого потребителя сохранять отдельный поведенческий контракт.

`SqlFormatter` сохраняет проверку токенов до и после преобразования.
Её нужно дополнить независимыми примерами: один ошибочный лексер может одинаково ошибаться с обеих сторон сравнения.
`BrowseSqlParser` продолжает отклонять неподдерживаемые формы.
`SqlStatementInspector.IsSafeToReExecute` не должен стать менее консервативным после рефакторинга.
Успешный parse SELECT сам по себе не доказывает отсутствие побочных эффектов.

Локальная диагностика syntax errors — отдельный поздний этап.
Нельзя помечать весь корректный SQL красным из-за ограничений частичного парсера.
Нельзя отправлять редактируемый запрос на выполнение ради подсказок.

## 8. Производительность

Сейчас контекст пересчитывается при открытии списка. При продолжении ввода фильтруется сохранённый набор кандидатов.
Само открытие включает несколько проходов по SQL, создание списков и дедупликацию.
Фильтрация сортирует все совпадения и заново назначает `ItemsSource`.

Диагностический замер `GetCompletionData` в текущем Debug/JIT на Windows:

| Размер буфера | Медиана | p95 | Выделено на вызов |
| --- | --- | --- | --- |
| 81 символ | 0,023 мс | 0,043 мс | 5 515 байт |
| 4 536 символов | 0,853 мс | 1,228 мс | 149 379 байт |
| 45 036 символов | 8,543 мс | 10,646 мс | 1 430 883 байта |

Методика: 5 прогревочных вызовов, 30 измерений, повторяющиеся завершённые SELECT перед текущим WHERE.
Каталог содержал три таблицы из раздела 4. Измерение не включает ranking, окно и отрисовку.
Это подтверждает зависимость от длины всего скрипта. Это не benchmark релизной версии и не оценка задержки пользователя.

Целевые бюджеты для Release на зафиксированной машине:

| Метрика | Цель |
| --- | --- |
| Работа UI-потока на одно изменение ввода | p95 ≤ 4 мс |
| От ввода до видимых актуальных подсказок, прогретый каталог | p95 ≤ 50 мс, p99 ≤ 100 мс |
| SQL-запросы к серверу на нажатие клавиши | 0 |
| Автодополнение при недоступном каталоге | Ключевые слова доступны без ожидания сети |
| Устаревшие ответы после смены документа/соединения | 0 принятых ответов |

Нагрузки: документы 1/10/100 тысяч символов, 1/10/100 тысяч объектов и до миллиона колонок каталога.
Измерять отдельно холодный запуск, фоновую загрузку, тёплое открытие списка, продолжение ввода и GC.
Большой каталог создавать синтетически. Не использовать пользовательские SQL-тексты как телеметрию.

Оптимизация по результатам замеров:

1. Кеш токенов и дерева по версии документа. Изменение локальной команды не пересобирает весь каталог.
2. Индексы имён и ограничение выдачи, например 100 лучших кандидатов. Лимит уточнить по UX-проверке.
3. Отмена устаревшей работы. Результат применяется только к совпадающим DocumentId, Version и ConnectionGeneration.
4. Тяжёлый разбор и поиск вне UI-потока. Быстрый локальный ответ не требует искусственной задержки.
5. Обновление списка без потери выбранного StableId и без лишнего пересоздания строк.

## 9. Пакеты реализации

Оценки относительные. Это порядок работ и зависимости, а не обещание сроков.
P0 исправляет неверные подсказки или изменение смысла текста. P1 закрывает ежедневные сценарии. P2 добавляет удобства.

| Пакет | Приоритет / размер | Работа | Зависимость | Критерий завершения |
| --- | --- | --- | --- | --- |
| A. Корпус и базовые измерения | P0 / S | Fixture-каталог, тесты provider и UI, сценарии F01–F09 | Нет | Найденные расхождения воспроизводятся автоматизированно |
| B. Лексика и границы команд | P0 / M | Общий лексер, escape/dollar strings, текущая команда и пустая область | A | F01/F04 проходят, Run/Explain выбирают прежние корректные границы |
| C. Имена и идентичность | P0 / M | Кавычки, цепочки, schema key, search_path, неоднозначные колонки | A, B | F02/F05 проходят без fallback в чужую схему |
| D. Принятие подсказки | P0 / M | TextEdit, Ctrl+Space, существующие скобки/алиасы, Undo, версия документа | A, B | UI-матрица вставки проходит |
| E. Безопасное раскрытие `*` | P0 / S | Отказ при недостоверной проекции JOIN/CTE | A | F07 не меняет результат. Причина отказа видна |
| F. Области видимости | P1 / L | Вложенные SELECT, CTE, derived tables, корреляция, LATERAL, UNION | B, C | F03/F06 и сценарии областей проходят |
| G. Контексты PostgreSQL и JOIN | P1 / M–L | INSERT/UPDATE/RETURNING/CONFLICT, USING, виды JOIN, несколько FK | C, F | Кандидаты допустимы в матрице SQL-контекстов |
| H. Функции и типы | P1 / M | Схемы, перегрузки, CALL, cast types, подсказка аргумента | D, F | F08 проходит, подсказка аргумента работает после вставки |
| I. Каталог и задержки | P1 / M | Снимки, отмена, загрузка без размеров, индексы, DDL invalidation | A, C | Бюджеты проверены на больших нагрузках |
| J. Дополнительные удобства | P2 / M | Шаблоны, достоверная локальная диагностика, ручной поиск системных объектов | F–I | Нет регрессий базового ввода |

После E точное раскрытие `*` возвращается для сложных JOIN только вместе с выходной моделью из F/G.
Не ждать завершения всех пакетов: B–E дают заметный эффект отдельными изменениями.
Измерения из A выполнять после каждого пакета, затрагивающего путь ввода.

## 10. Матрица приёмки

Использовать единый формат фикстур: SQL с курсором, каталог, контекст сессии, ожидаемые кандидаты и итоговый текст после accept.
Отдельно проверять запрещённые кандидаты. Проверка только наличия нужного имени не обнаруживает шум из чужой области.

| ID | Вход или действие | Ожидаемый результат |
| --- | --- | --- |
| T01 | `se|` в новой команде | SELECT выше SET и объектов каталога |
| T02 | Две команды с разными FROM, курсор поочерёдно в каждой | Источники соседней команды отсутствуют |
| T03 | `SELECT 1; |` | Новый контекст, без таблиц предыдущей команды |
| T04 | `SELECT u.| FROM public.users u` | `id`, `name`, несмотря на FROM справа |
| T05 | `users` при двух схемах и известном search_path | Колонки только реально разрешённой таблицы |
| T06 | `missing.users` | Неизвестный объект. Нет колонок `public.users` |
| T07 | `public.users.|` | Нет `audit_only` |
| T08 | `foo`, `"foo"`, `"Foo"`, `"a""b"`, Unicode и имена с пробелами | Точное разрешение и обратимая вставка |
| T09 | Общий `id` двух таблиц / self JOIN | Раздельные варианты с правильными алиасами |
| T10 | Незакрытая `"na|` | Подсказки идентификаторов, корректное закрытие кавычки |
| T11 | Обычная строка, E-string, dollar tag с цифрой/Unicode, вложенный комментарий | Нет автоматического completion внутри текста |
| T12 | `;` внутри E-string и dollar string | Разбиение только на реальные команды |
| T13 | Подзапрос в WHERE, курсор после его `)` | Восстановлен внешний Predicate |
| T14 | Внутренний алиас совпадает с внешним | Внутреннее имя скрывает внешнее только в своей области |
| T15 | Derived table с `id AS customer_id` | `q.` предлагает `customer_id` |
| T16 | CTE с `u.*`, явным списком, цепочкой CTE и RECURSIVE | Точная проекция, правильная видимость, нет бесконечной рекурсии |
| T17 | CTE с DML RETURNING и `VALUES` | Известные выходные имена доступны |
| T18 | Обычный FROM-подзапрос / LATERAL / коррелированный EXISTS | Разные корректные наборы внешних ссылок |
| T19 | UNION, курсор в каждой ветви | Источники ветвей не смешиваются |
| T20 | JOIN с двумя FK / составным FK / ранний ON перед следующим JOIN | Выбор правильной связи текущего JOIN |
| T21 | CROSS JOIN / NATURAL JOIN | Нет предложения недопустимого ON/USING |
| T22 | JOIN USING (`|`) | Общие колонки только двух сторон текущего JOIN |
| T23 | Раскрытие `*` с USING/NATURAL/OUTER JOIN | Та же форма и значения результата либо понятный отказ |
| T24 | INSERT/SET/CONFLICT/RETURNING | Колонки и выражения соответствуют позиции |
| T25 | SELECT alias в ORDER BY и WHERE | Алиас доступен только там, где это допускается |
| T26 | `schema.function`, quoted function, перегрузки, CALL | Правильная схема, кавычки и вид callable |
| T27 | Вложенный вызов и запятая внутри строки/массива | Выделен правильный аргумент |
| T28 | Ctrl+Space после префикса и в середине слова | Правильные фильтр и диапазон замены |
| T29 | Accept перед `(`, перед существующим алиасом и закрывающей кавычкой | Нет дубликатов, курсор на ожидаемом месте |
| T30 | Accept + автоалиас → Undo → Redo | Одна атомарная операция |
| T31 | Escape, Backspace после нулевого результата, повторный Ctrl+Space | Предсказуемый жизненный цикл одного окна |
| T32 | Быстрый ввод, paste, IME, смена вкладки/соединения во время completion | Нет чужой вставки и устаревших результатов |
| T33 | Каталог недоступен, refresh отменён, старый refresh заканчивается позже нового | Старый снимок не перезаписывает новый, базовые подсказки работают |
| T34 | Исключённая схема связана FK с включённой | Исключённые отношения не возвращаются через JOIN suggestions |
| T35 | CREATE/ALTER TABLE, SET search_path, temp table в текущей сессии | Обновление достоверных metadata либо явная неизвестность |
| T36 | 100 тыс. символов и большой каталог | Выполнены бюджеты задержки, ввод остаётся отзывчивым |

Уровни проверки:

- Core: токены, границы команд, области видимости, разрешение имён, ранжирование и TextEdit.
- Provider: фикстуры каталога без сети, полный набор кандидатов и точная вставка.
- Avalonia headless: клавиши, popup, Undo/Redo, переключение вкладок и защита версии документа.
- Живое приложение: реальный popup, IME, DPI, обе темы и сценарии быстрого набора.
- Изолированный PostgreSQL: search_path, quoted names, temp objects, FK и формы результата при раскрытии `*`.
- Release/NativeAOT: публикация целевых платформ и замеры пути ввода.

Для лексера добавить генеративные проверки: каждый проход продвигает позицию, spans остаются в документе, незавершённый ввод не вызывает исключений.
Вставки и удаления внутри комментариев, строк и скобок должны сохранять эти свойства.
